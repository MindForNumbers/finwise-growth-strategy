# The Validation · FinWise

> Module 5 · Experimentation Methods. The experiment brief that tests the bet.

## Method

50/50 A/B Test on a cohort of net-new trial sign-ups. Why it fits: We must test this on a fresh cohort to isolate the behavioral impact of the new widget. Testing on legacy users who are already accustomed to the passive reporting dashboard would contaminate the behavioral data. Furthermore, targeting a leading indicator allows an A/B test to reach statistical significance rapidly, whereas testing against the 2% lagging conversion rate would take months.

## Hypothesis + primary metric

If we deploy the active "Capital Efficiency Widget" to surface daily ROI opportunities on the main dashboard, then Widget Execution Velocity (high-leverage actions per session) moves by a +20% relative lift.

## Guardrail + read date

- **Guardrail:** Bank/Accounting Data Sync Drop-off. Forcing users to confront "inefficiencies" requires deep data access; our onboarding completion rate must not degrade by more than 2%.
- **Read date:** 21 Days post-launch. This allows a 1-week acquisition cohort to fully run through the 14-day reverse trial window, providing a clean data set without peeking early.
